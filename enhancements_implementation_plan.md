# Training Alignment & allrounder_legacy — Implementation Plan

## What changes and why

### 1. Hyperparameter alignment (all 9 models → train_l1.py exact)

Current `train_base_models.py` uses `train_l1_specialist.py` defaults (L2, 25k features). Legacy `train_l1.py` uses different values:

| Config | Current (wrong) | Legacy `train_l1.py` (correct) |
|---|---|---|
| `penalty` | `l2` | **`l1`** |
| `max_features` | `25,000` | **`5,000`** |
| `min_df` | `5` | **not set (sklearn default=1)** |
| `prune_threshold` | `0.001` | **`0.05`** |
| `squash_augment` | `True` | **`False`** (optional flag, off by default) |
| `C` | 0.1 ✓ | 0.1 ✓ |
| `dual` | False ✓ | False ✓ |
| `class_weight` | balanced ✓ | balanced ✓ |

> [!IMPORTANT]
> `squash_augment=False` halves training data volume vs current. This is correct per `train_l1.py` — augmentation was an explicit opt-in flag, not the default.

> [!IMPORTANT]
> `max_features=5_000` + `penalty='l1'` + `prune_threshold=0.05` together will produce **~300–2,000 sparse weights** (not 23k) — this is the intended legacy behaviour.

After this fix, `SVM_CFG_LEGACY` and `TRAIN_CFG_LEGACY` (currently separately defined) become identical to main configs and are removed.

### 2. `allrounder_legacy` — Option B (ProtectAI recipe sources)

Option B: Download the same raw source datasets from HuggingFace that fed the `t2/` pipeline. All 7 fetch scripts for the new sources already exist in `scripts/sources/`.

### 3. Startup auto-training — all 10 models

`main.rs` `ensure_base_models()` currently only checks `allrounder.weights.json`.

**Change**: Collect list of ALL missing required model weight files and print them. Trigger `train_base_models.py` if any are missing. The training script already skips models whose `.weights.json` cache files exist (`if not path.exists() or args.force`), so only missing ones are trained.

Required weight files to check:
- `allrounder.weights.json` (trained on all category data)
- `allrounder_legacy.weights.json` (trained on ProtectAI recipe sources)

The 8 specialist aliases (`instruction_override`, `roleplay_jailbreak`, etc.) are resolved at runtime in `svm_base.rs` — they don't have their own weight files unless a specialist file is explicitly present.
